# Парсинг данных

Данные `/app/data` собираются скриптами `scripts/parse_*.py`: `parse_gdz.py` —
основные учебники 6–11 классов, `parse_kontur.py` — контурные карты,
`parse_euroki_bulk.py` — массовый сбор 3–5 и 10–11 классов, `parse_euroki.py` —
литература. Скрипты запускаются вручную (не в CI): наполнение — отдельная операция,
результат коммитится в репозиторий.

## Массовый euroki (2.1)

Инвентарь: `scripts/euroki_books.json`, автосбор — `scripts/discover_euroki.py`.
Для 5 класса — 42 книги. Скрипт умеет:

* `--resume` — готовый JSON не перекачивается, но возвращается в манифест
  (иначе после обрыва книга пропадала из каталога);
* `--slugs-file` и `--manifest` — шарды, по процессу на группу книг;
* проверку картинок и пропуск битых ссылок;
* атомарную запись через `.json.part`;
* при 403/429 — `sleep(60)`, смена User-Agent, прокси из `HTTPS_PROXY`, если задан.

После партии: `normalize_new_books.py` → `sync_bulk_catalog.py` →
`validate_data.py` → `write_stats.py` → `build_search_index.py`.
Собран 5 класс: 43 файла, 33 693 задания. В каталоге —
88 238 заданий, 185 учебников, 15 предметов (3–11 классы).

## Источник

Выбран **gdz-raketa.ru** — первый источник из списка ТЗ, который отдаёт условия и
решения **текстом** (не картинками) и не блокирует обход.

Что проверялось до него:

| сайт | результат |
| --- | --- |
| gdz.ru | решения и ответы — картинками, текст не извлекается (для контурных карт это то, что нужно — см. `parse_kontur.py`) |
| euroki.org | часть учебников отдаёт 404, но литература и др. — вопросами и ответами **текстом** (используется для Коровиной, см. `parse_euroki.py`) |
| otvet.plus | только старый Виленкин (2014), редакции 2023+ нет |
| reshalka.com | ответы приходят в закодированном виде, разбор нецелесообразен |
| gdz-raketa.ru | текст условий и ответов + метаданные, robots.txt не запрещает контентные страницы — **основной вариант** |

Условия использования: парсер уважает `robots.txt`, ходит с честным User-Agent
(`GdzNelBot/1.0`) и выдерживает паузу между запросами. При 403/429 — минутная
пауза и смена User-Agent.
Данные используются для личного образовательного проекта с указанием источника.

Источники по задачам:

* основные учебники — **gdz-raketa.ru** (текст; `parse_gdz.py`);
* контурные карты (Матвеев, Тороп 6–9) — **gdz.ru** (сканы страниц-разворотов
  скачиваются локально; `parse_kontur.py`);
* литература (Коровина 6–9) — **euroki.org** (вопросы и ответы текстом;
  `parse_euroki.py`);
* массовые 3–5 и 10–11 классы — **euroki.org** (`parse_euroki_bulk.py`),
  включая сканы страниц для русского языка и литературы;
* добор единичных пропусков — euroki.org → otvet.plus → reshalka.com
  (`fill_gaps.py`).

## Модель данных

Формат файла учебника — `docs/SPEC.md` (раздел «JSON для заданий»), схема —
`docs/data-schema.json`, проверка — `scripts/validate_data.py`.

Номера задач — строки:

* математика (Виленкин) — как в учебнике: `1.1 … 3.193`, `4.1 … 6.126`;
* русский язык (Ладыженская) — сплошная нумерация: `1 … 406` (часть 1), `407 … 754` (часть 2);
* английский, биология, история, обществознание — на источнике у страницы нет
  номеров упражнений, поэтому номер = `страница.K`, где K — порядок блока «Номер K.»
  на странице (например `5.2` — вторая задача на стр. 5);
* если на странице две группы заданий с одинаковыми номерами, дубли получают
  суффикс: `9.1`, `9.2`, `9.1-2`, `9.2-2`.

`section` — раздел/модуль/параграф:

* математика — `§1 … §6` раскладываются по номеру задания (`section_map` в конфиге:
  страницы источника заголовков параграфов не несут; названия параграфов сверены с
  учебником: «§2. Действия со смешанными числами», «§3. Отношения и пропорции»,
  «§4. Действия с рациональными числами», «§5. Решение уравнений»,
  «§6. Координаты на плоскости»);
* русский — название параграфа («3. Литературный язык и его нормы»),
  при отсутствии — заголовок раздела (`ПОВТОРЕНИЕ ИЗУЧЕННОГО В 5 КЛАССЕ`);
* английский — заголовок страницы учебника (`Who's who? — Кто есть кто?`);
* биология/история — `§N. Название` или заголовок (`ВОПРОСЫ И ЗАДАНИЯ`);
* обществознание — параграф (`§ 2. Человек — личность`) или рубрика
  (`ПРОВЕРЯЕМ НАШИ ЗНАНИЯ И УМЕНИЯ`), для страниц с рубриками без «Номер K.» —
  номер = `страница.порядок рубрики`.

Раздел переносится на следующие страницы, пока не встретится новый заголовок, —
на источнике заголовок печатается не на каждой странице.

## Особенности страниц gdz-raketa.ru

* Два варианта маркера: «Номер 1.1.» и «Номер. 4.31.» — поддержаны оба.
* Дроби — `<span class="fraction">2/3</span>` внутри абзаца; парсер разворачивает
  инлайн-теги, чтобы «В(–3 2/3); С(–5)» не рвалось на три строки.
* В конце страницы — служебный блок («Конец страницы», «Переход на другие
  страницы», «Содержание», форма жалобы), парсер останавливается по маркерам.
* Часть задач на источнике **без ответа** (после «Ответ:» сразу «Конец страницы»)
  или с пометкой «Продолжение на следующей странице» — такие задачи в данные не
  попадают. В приложении они видны как серые зачёркнутые ячейки, а не как
  битые карточки.
* Переведённые задания по английскому: условие — оригинал + перевод через « — »,
  перевод решения попадает в блок «Перевод:» внутри решения.

### LaTeX-конвертер (математика, 2026-10-19)

Страницы Макарычева отдают формулы вперемешку с обрывками LaTeX: `\( \)`,
`\[ \]`, `\frac`, `\dfrac`, `\mathbf{…}`, таблицы `\begin{array}`. Парсер
прогоняет текст через конвертер в читаемую запись:

* `\dfrac`/`\tfrac` → `\frac`, `\left`/`\right` → скобки, `\cdot` → `·`,
  `\geq`/`\leq`/`\neq` → `≥`/`≤`/`≠`, `\in` → `∈`;
* дроби `\frac{a}{b}` → `a/b` со скобками по контексту;
* шрифты (`\mathbf{…}`, `\mathrm{…}`, `\boldsymbol{…}`) разворачиваются в содержимое;
* таблицы (`\begin{array}`, `\hline`, `\&`) вычищаются;
* многострочные `$$…$$` (таблицы-`array`) схлопываются и конвертируются целиком —
  построчный проход их не видел и оставлял `{x}` и `« : »`;
* пробелы внутри числовых сторон дроби схлопываются (`\mathbf{9 0}` → `90`);
* фолбэк источника: `<sup>\х + 4</sup>` без `\frac` — это знаменатель дроби из
  предыдущего текста («1/х + 4» → «1/(х + 4)»); правило применяется только
  когда рядом есть `$$…$$` или `\[a-zA-Z]`, литеральные «\[у]» и цены не трогаются;
* порядок правил важен: `\\` (перенос строки) обрабатывается раньше `\\[;,!: ]`.

## Контурные карты (gdz.ru)

Каждая страница книги на gdz.ru — разворот («Страница 2–3») со сканами решённых
карт. `parse_kontur.py` скачивает их **локально** (jpeg, ширина ≤ 1600, q84):

    app/data/geo/img/matveev-6/str-2-3.jpg

в задаче — относительные пути `data/…/img/…`, условие «Страница 2–3 контурных
карт.», раздел «Контурные карты»; приложение не зависит от чужого сайта. HTML
кэшируется в `/tmp/opencode/kontur-cache`, книги по умолчанию пропускаются
(`--force` пересобирает).

## Литература (euroki.org)

Единственный из проверенных источников, кто отдаёт Коровину **текстом**:
страница книги = карточки «рубрика → вопрос → ответ». `parse_euroki.py` собирает
каждую часть отдельным файлом (`literature/korovina-6-1.json`), номера задач —
`страница.K` (K — порядок карточки на странице).

Нюансы источника:

* слаги страниц двух видов: `1-str-107` и `1-str-102-148` (суффикс-хэш) —
  номер страницы берётся из первого числа;
* нумерация вопросов внутри карточек повторяется по рубрикам — потому в номере
  задачи K это просто порядок карточки, а не номер вопроса из учебника;
* у части карточек euroki не разметил блок вопроса: если первый абзац ответа
  похож на вопрос (вопросительный знак или типичное начало задания) — он
  выносится в условие, иначе условие «Страница N. Рубрика.»;
* рубрики-инструкции длиннее 48 символов подрезаются по запятой/двоеточию,
  чтобы не раздувать чипы разделов;
* у задач стоит `source: euroki.org` и `sourceUrl` страницы.

## Запуск

```bash
# одно превью без записи (в /tmp/gdz_preview_<книга>.json)
uv run --with beautifulsoup4 scripts/parse_gdz.py vilenkin-6-1 --limit 10 --dry

# полный сбор всех учебников (пишет в app/data), устойчив к обрывам сети
uv run --with beautifulsoup4 scripts/parse_gdz.py all

# продолжить прерванный сбор: уже собранное не перекачивается
uv run --with beautifulsoup4 scripts/parse_gdz.py all --resume

# контурные карты (gdz.ru → локальные сканы), можно одну книгу
uv run --no-project --with beautifulsoup4 --with pillow scripts/parse_kontur.py
uv run --no-project --with beautifulsoup4 --with pillow scripts/parse_kontur.py torop-9

# литература Коровиной (euroki.org), можно одну часть
uv run --no-project --with beautifulsoup4 scripts/parse_euroki.py
uv run --no-project --with beautifulsoup4 scripts/parse_euroki.py korovina-9-2

# проверка данных
uv run --with jsonschema scripts/validate_data.py
uv run python scripts/write_stats.py
```

## Как добавить новый учебник

1. Разведать страницы источника: режим «одна задача на страницу» (URL вида
   `…-nomer-{i}/`) или «страница с блоками Номер K.» (`…/stranitsa-{n}/`).
2. Добавить книгу в конфиг `BOOKS` (scripts/parse_gdz.py): `subject`, `textbook`,
   `kind` (`single` или `page`/`rubric`), диапазон URL (`urls` или `pages` +
   `page_pattern`), при необходимости `section` (раздел по умолчанию) и `section_map`
   (раскладка разделов по номеру задания, если заголовков на страницах нет).
3. Добавить запись в `app/data/catalog.json` (id, title, author, year, file).
4. Проверить на превью: `scripts/parse_gdz.py <id> --limit 10 --dry`, посмотреть,
   что условия/ответы разобрались корректно.
5. Полный сбор: `scripts/parse_gdz.py <id>`, затем `validate_data.py` и
   `write_stats.py` (см. выше).

Правка данных вручную (если источник сломался): файл учебника —
`app/data/<предмет>/<учебник>.json`, задание — объект в `tasks` (`number`, `section`,
`condition`, `solution`, `answer`). После правок — те же две команды проверки.
